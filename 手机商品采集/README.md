# 抖音商品采集

原生 Android 应用，包名 `local.ai.collector`。默认从**官方考古加 App 当前筛选列表**采集：按配置切换数据周期，逐件进入详情查看价格，进入抖音商品后采集规格、报价与热销标记，再返回考古加处理下一件。本次暂不采款式图片。也保留“单件采集”入口。结果保存在手机，可配置网站接收接口回传。

这是独立应用，现有“百亿补贴采集”及其记录保持在原应用中。

## 当前范围

- 来源使用官方考古加 App `com.fz.kaogujia`，商品采集支持抖音商城 `com.ss.android.ugc.livelite` 和抖音 `com.ss.android.ugc.aweme`，Android 11 及以上。
- 标题下方、采集与结果标签上方放置平台选择和“采集设置”。当前平台列表仅有“抖音”，整页采集、结果和设置都属于抖音页面，没有其他平台占位选项。
- “采集设置”统一编辑周期、商品数量、单件规格组合上限和款式图片开关，主页面只显示保存后的摘要。周期默认 30 日，图片默认关闭。批次显示总量、完成数、失败数及当前商品，可开始、继续、暂停或结束。
- 通过手机无障碍服务读取与操作界面，不依赖电脑持续连接。
- 规格名称来自当前商品，不固定为“颜色”“款式”；价格以页面实际标签与读数保存，金额单位为分，未核对的值保留为空。
- 当前 `capture_sku_images` 默认关闭，只采规格、价格与热销标记，不打开款式大图。规格记录中的 `image_status=not_requested` 显示为“未采集图片（本次未启用）”，不作为失败或缺失字段，也不会因此标记“部分完成”。
- 已有主图和规格图片仍可查看、保存与回传。历史规格图片来自页面预览截图裁切；旧网页模式可下载页面接口提供的原图。`video_url` 只保留实际取得的视频链接，缺失时明确显示未提供，不猜测。
- 任务可暂停、继续或结束；已保存记录支持查看、导出 JSON 和回传。默认单件最多采集 24 个组合，可在应用中调整。
- 无法核对的规格、价格保留说明；达到采集上限或报价未完整核实时显示“部分完成”。本次未启用图片不影响规格与价格采集的完成状态。

平台选择通过注册表和 `showPlatformPage(id)` 路由切换整个平台页面，包含采集、结果和该平台的设置状态，页面会缓存而非每次重新创建。当前只注册抖音；后续平台须登记各自的独立页面后才会显示。

## 使用

1. 安装 `dist/手机商品采集.apk`，打开“手机商品采集”。
2. 点击“打开无障碍设置”，开启“手机商品采集”。如果系统要求额外允许此应用的受限设置，按手机系统提示完成。
3. 分别确认官方考古加 App 和用于打开商品的抖音 App 已登录。

**工作台接单**：在电脑打开「手机采集」，生成六位配对码。在手机采集页点「连接工作台」，输入电脑提供的 HTTPS 地址、证书 SHA-256 和配对码。配对后点「开启待命」，保持手机解锁并停留在采集 App，工作台下发的任务会自动开始。任务进行中可在电脑查看阶段和回传情况。遇到需要处理的提示，在手机上处理后用「继续当前批次」恢复。每件商品在收到入库回执前会保留在手机上，有网后自动补传。

在开发环境使用 USB 转发时，可以使用 `http://127.0.0.1:3000`，证书指纹留空。局域网 HTTPS 入口的启动方法见[工作台说明](../ai选品工作台/README.md#手机采集任务)。

**官方 App 批量采集**：

1. 在顶部“考古加 App 批量采集”点击“打开考古加 App”，保留要采集的商品列表与筛选条件。打开按钮恢复 App 的已有页面，不强制返回首页。
2. 回到采集应用，点击顶部“采集设置”，选择“昨日”“7日”或“30日”，填写商品数量及单件规格组合上限，保存后点击“开始采集当前列表”。本轮测试保持款式图片关闭。
3. 自动化按所选周期切换 App 的数据范围，从当前筛选列表逐件进入详情，点击查看价格，再进入对应抖音商品读取规格、价格和热销标记。
4. 当前商品保存后返回考古加，继续处理下一件，直到达到本次商品数或需要人工处理的状态。

已有暂停批次使用“继续当前批次”，继续时沿用该批次已经保存的参数。要更换参数，先结束当前批次，再重新开始。名单可通过“预览商品名单”核对；来源暂未提供商品 ID 时不会编造 ID。

设置弹窗明确标注“设置用于下一次任务”。保存只更新配置与页面摘要，不主动暂停、重启或重新创建当前任务；图片开关默认关闭，需要在新任务中明确启用才采集款式图片。

周期配置是 App 的统计周期选项，不是脚本计算的自然日期区间：

| 页面选项 | 传入脚本的值 |
| --- | --- |
| 昨日 | `yesterday` |
| 7日 | `7d` |
| 30日（初始默认） | `30d` |

配置不转换成网页接口的数字周期，也不根据电脑当天日期重新计算起止日。周期与商品数在开始任务时保存。

**单件采集**：在抖音商品 App 打开目标商品详情页；回到采集应用，在“单件采集”点击“采集当前商品”。应用会打开规格弹窗，逐款采集规格、价格与热销标记，本次不采款式图片。已打开规格弹窗时直接采集；“共 N 款”只用于核对数量。

采集期间保持手机解锁，避免手动切换商品或规格。需要操作手机时先暂停任务。批次正在执行或暂停时，单件任务控制会停用，防止同时操作不同商品。完成后进入“结果与回传”查看每个组合的规格、价格与热销标记；已有图片记录仍可查看，没有网站接口时可先导出 JSON。

“暂停批次”用于稍后继续；“结束批次”保留已完成记录，之后可从考古加 App 当前列表开启新批次。

遇到规格入口未识别、商品页异常或弹窗遮挡时，应用会显示当前处理提示。保留目标商品页，处理后点击“继续当前任务”。“结束并保留结果”会保存已经采集到的内容。

## 删除记录与重试失败商品

在“结果与回传”中，每条已保存记录都有“删除记录”。确认框显示具体商品及店铺，确认后只删除手机上的该条记录，并清理没有其他记录、活动任务或队列引用的独占图片缓存。正在采集、暂停未结束或仍是当前批次处理项的记录不能删除；任务状态无法核对时也会拒绝删除。删除本地记录不会执行服务器删除，也不会停止当前采集任务。

只有批次已完成且失败数大于零时，才显示“重试失败商品”。点击后使用原批次重试失败项，跳过已经完成或部分完成的商品，不重新读取名单，也不改采集设置。已有成功记录保留。若准备重试后未能立即启动，可使用“继续当前批次”。

批次完成表示队列已走到末尾，不等于每件都完整成功。核对结果时应分别查看完成、部分完成、失败和待处理，并检查各件的实际规格与报价。

## 运行准备与卡住排查

运行前确认采集应用已开启无障碍服务、允许通知，电池策略设为“无限制”；手机保持解锁，考古加与抖音已经登录。周期初始为 30 日，本次商品数按需要填写。

本机真机排查曾发现：HyperOS 切到抖音后冻结了采集应用的 UID，即使界面仍显示无障碍已连接，自动操作也会停止。已加入 `CollectionKeepAliveService` 特殊用途前台服务，采集运行时显示通知，暂停、完成或结束后停止。当前测试手机已配置允许通知、电池无限制，调试侧的电池白名单和 `active` 状态也已设置。

卡住时按以下顺序检查：

1. 返回采集应用查看任务提示，先区分正在运行、已暂停或已结束。运行时检查采集通知；暂停、完成或结束后没有该通知属于正常状态。
2. 如果停在抖音且无障碍仍显示连接，检查采集应用的通知权限与电池“无限制”设置。调试时继续核对 UID 是否被冻结，以及白名单、`active` 状态，不能只根据无障碍连接判断任务仍在执行。
3. 如果是登录、系统跳转或商品页面提示，保留当前批次，处理提示后点“继续当前批次”。不要另开新批次覆盖待核对结果。调试观察使用截图和只读任务文件，避免同时运行 `uiautomator dump`。

官方 App 的 10 件完整测试仍在进行，尚未确认 10 件全部成功；应逐件查看已保存结果及完成、部分完成或失败状态。

## 官方 App 登录与旧网页模式

官方考古加 App 使用自身的登录状态，与网页 Cookie、电脑 Chrome 用户目录独立。默认流程通过无障碍操作官方 App，不导入 `D:\ChromeDebug\User Data`，也不承诺从 App 登录提取接口鉴权。

“展开旧网页模式”保留之前的“打开旧网页登录与筛选”入口。该模式使用采集应用内独立的 WebView 会话，旧的网页名单、二维码与相册清理流程继续保留兼容能力，不作为默认启动入口。

默认 App 流程为“当前筛选列表 → 切换配置周期 → 商品详情查看价格 → 抖音商品规格采集 → 返回下一件”。如果 App 页面、价格入口或目标商品无法核对，任务保留提示和进度，不把未读取的数据写成已采集。

## 回传设置与保留规则

“结果与回传”优先显示采集记录和待回传状态，点击“回传设置”展开配置，填写**完整的接收接口地址**并保存。回传密钥可选，填写后作为 `Authorization: Bearer <密钥>` 发送。地址为空时只保存到手机。

记录保存后以及重新打开应用时会尝试回传，也可点击“立即回传”。每轮遇到失败就停止，记录和图片继续保留，待下次重试。当前没有常驻的定时重试服务。

服务器确认对应记录和版本已经接收后，应用才标记回传成功并清理不再被其他待回传记录引用的主图和规格截图。记录 JSON 继续保留。图片清理失败不会撤销接收状态；`image_cleanup_pending` 为 `true` 表示仍有缓存未能清理。导出 JSON 包含记录及图片路径，不打包图片文件。

应用内数据放在自身私有目录：`records/` 保存记录，`images/` 保存规格截图，`active_task.json` 保存进行中的任务。卸载应用或清除应用数据会移除这些内容。

## 网站接收协议

请求为 HTTP POST，`Content-Type: application/json; charset=utf-8`。本次不请求款式图片的规格记录包含 `image_status: "not_requested"`，没有图片附件时 `images` 为空数组。已有图片记录仍支持通过 Base64 随 JSON 回传。当前调试版支持 HTTPS 和局域网 HTTP。

请求头 `Idempotency-Key` 为 `<record_id>:<revision>`，接收端应按这一组合去重。同一记录重新保存时 `revision` 增加。

下面的含图示例用于兼容已有图片记录；本次未启用款式图片时，规格中以 `image_status: "not_requested"` 代替 `image`，并省略相应的 `sku_image` 附件。没有请求图片不等于图片采集失败。

```json
{
  "schema_version": 1,
  "device_id": "手机采集应用生成的标识",
  "device_model": "厂商 型号",
  "record_id": "采集记录编号",
  "revision": 1,
  "record": {
    "record_id": "采集记录编号",
    "revision": 1,
    "task_id": "任务编号",
    "platform": "douyin_mall",
    "source_application": "com.ss.android.ugc.livelite",
    "title": "商品标题",
    "video_url": "",
    "main_image": {
      "file": "/data/user/0/local.ai.collector/files/main_images/商品编号.jpg",
      "mime": "image/jpeg",
      "width": 900,
      "height": 900,
      "source_url": "https://图片服务器/商品主图.jpg"
    },
    "product_tags": ["页面实际标签"],
    "skus": [
      {
        "name": "所选规格组合",
        "specifications": {"颜色分类": "米色旗舰款"},
        "hot": true,
        "price_before_label": "页面价格标签",
        "price_before_coupon_fen": 13990,
        "price_after_label": "券后价",
        "price_after_coupon_fen": 3390,
        "image": {
          "file": "/data/user/0/local.ai.collector/files/images/任务编号/0001.png",
          "width": 900,
          "height": 900,
          "source": "抖音商城已选规格顶部图片预览裁切"
        }
      }
    ]
  },
  "images": [
    {
      "kind": "main_image",
      "spec_index": -1,
      "image_index": 0,
      "file_name": "商品编号.jpg",
      "mime_type": "image/jpeg",
      "sha256": "主图内容的 SHA-256 十六进制值",
      "data_base64": "主图文件的 Base64 内容"
    },
    {
      "kind": "sku_image",
      "spec_index": 0,
      "image_index": 0,
      "file_name": "0001.png",
      "mime_type": "image/png",
      "sha256": "图片内容的 SHA-256 十六进制值",
      "data_base64": "图片文件的 Base64 内容"
    }
  ]
}
```

`kind=main_image` 对应 `record.main_image`，`spec_index=-1`、`image_index=0`；`kind=sku_image` 保持原有规格附件字段，`spec_index` 是 `record.skus` 的零起始下标。附件的 `mime_type` 按实际文件头识别，不能将所有图片都当作 PNG。仅当记录确实引用了图片文件时，文件缺失或格式无法识别才会阻止该条回传；`not_requested` 且没有图片引用的记录可正常回传。

价格可能为空，不能用零替代未采集值。`video_url` 只是链接元数据，不在 `images` 附件中。`record` 还会包含保存时间、采集状态及核对说明等字段，接收端应保留这些字段。

**接收端持久化记录和图片后**，返回 2xx 及以下 JSON：

```json
{"acknowledged": true, "record_id": "与请求完全相同", "revision": 1}
```

`acknowledged` 必须为布尔值 `true`；`record_id` 必须相同，`revision` 必须为相同的数字。缺少版本、编号不符、非 2xx 或无效 JSON 都不会触发清理。正在回传旧版本时若手机又保存了新版本，旧回执不能确认或删除新版本的数据。

## 构建与源码

调试运行中的本机无障碍采集时，使用 ADB 截图和只读任务文件观察状态；不要同时执行 `uiautomator dump`。Android 的 UiAutomation 会临时抑制其他无障碍服务，导致本应用服务重连并按设计暂停批次。此时在应用中点击继续即可，已保存的记录不会删除。

此前启用图片采集时，已在连接的真实手机上通过单件入口验证两件商品。olayks 单规格保存展示价 187.90 元、补贴价 112.72 元和对应图片；美的 FG208Air 从大图自动切到小图，依次保存奶茶色、海盐蓝两款，各为券前价 229.00 元、券后价 133.00 元，并分别保存 1080×1080 图片及海盐蓝热销标记。报价是测试时该账号的页面读数。原始记录与图片副本放在本地 `测试记录/`。本次批量测试已改为只采规格、价格与热销标记，尚未确认 10 件全部成功；网站地址尚未配置，实际网站联调待接收端接入。

项目使用 Java 与 Android SDK 工具构建，二维码生成和校验使用 `libs/core-3.5.3.jar` 中的 ZXing。构建时保留 `libs/` 和 `assets/` 目录。在 PowerShell 中进入本目录执行：

```powershell
.\build.ps1
```

默认 JDK 为 `D:\Android Studio\jbr`，SDK 为 `%LOCALAPPDATA%\Android\Sdk`，使用 Build Tools `36.0.0` 和平台 `android-37.0`。可通过脚本的 `JdkRoot`、`SdkRoot`、`BuildToolsVersion`、`PlatformVersion` 参数更换。

构建输出在 `dist/手机商品采集.apk`。`.signing/` 保存本应用的升级签名，后续构建请保留该目录及配套口令文件。

- `MainActivity.java`：官方 App 来源与周期配置、采集控制、结果查看和导出。
- `KaoguActivity.java`：旧网页模式的考古加登录与筛选入口。
- `BatchStore.java`：批次商品名单及进度。
- `MallNavigator.java`：抖音商城相册扫码、商品页进入及身份识别。
- `QrAlbum.java`：二维码生成、相册暂存及对应图片恢复清理。
- `CollectorService.java`：任务状态、规格报价采集、可选图片及进度保存。
- `CollectionKeepAliveService.java`：采集运行期间的前台通知，暂停、完成或结束时停止。
- `DouyinAdapter.java`：抖音商城界面识别。
- `RecordStore.java`：原子保存、待回传队列、回执核对与图片清理。
